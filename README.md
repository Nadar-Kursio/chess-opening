# Opening Lab

An interactive chess opening course, live at **https://chesslab.dev**. Every
move comes with a reason, every reason is checked by an engine before it ships,
and when your opponent plays something else, the course answers *that* move too.

The repository is two programs with a one-way pipe between them:

1. **A Python content compiler** (`src/`) — the source of chess truth. Course
   material is authored by hand as Python modules and compiled, validated and
   enriched into JSON.
2. **A Next.js site** (`web/`) — the presentation. It consumes that JSON at
   build time and exports plain static pages; there is no server anywhere.

Nothing flows backwards: the site never generates chess facts, and the compiler
knows nothing about React. The wiki's **Architecture** page walks through the
moving pieces.

## Layout

```
src/
├── build.py            the compiler: validate, derive, emit web/content/
├── content/
│   ├── openings/       one module per opening — SAN moves + authored prose
│   ├── sections.py     the families the nav groups by
│   ├── structures.py   the shared pawn-structure cards
│   ├── common.py       move notes shared between openings
│   ├── primer.html     the front page's prose
│   ├── notes/          the author's own notes — deliberately unverified
│   └── evals/          Stockfish scores per position — generated, committed
└── engine/             board serialisation, move intel, notes parsing

web/
├── app/                routes: /, /openings/, /openings/[opId]/[lineSlug]/ …
├── components/         shell, opening page, and the study island
├── lib/                content loader/types, chess reading, study state, storage
├── styles/             the design system; tokens.css first, responsive.css last
├── content/            GENERATED by --emit; gitignored
└── tests/              the artifact smoke: jsdom over the real export

tests/                  Python: content shape checks + the emit contract
```

## What the compiler guarantees

`src/build.py` replays every move of every line, deviation and game on a real
board (python-chess) and **fails the build** on an illegal move, a capture or
check marker the move does not earn, a malformed win-rate record, or a missing
line slug. It then derives everything the site must never compute for itself:
board layouts, legal-move lists (the drill's answer key and the board's move
dots), arrow/tactics annotations, and the Stockfish evals attached from
`src/content/evals/`. The `opening-research` skill documents how content is
researched and verified before it is written down at all.

The site ships only the openings named in `PORTED` in `src/build.py`. Adding
one is data-only: author a `slug` per line, append the id, re-run the evals
script if the opening is scored. If the app needs code for a new opening, that
is a bug in the app.

## Working on it

```bash
.venv/bin/python3 src/build.py --emit           # validate everything, write web/content/
.venv/bin/python3 -m unittest discover tests    # content + emit contract
```

Then, from `web/`:

```bash
npm ci            # once
npm run dev       # edit-refresh loop on localhost
npm run build     # static export into web/out/
npm test          # the artifact smoke: jsdom drives the exported pages
```

The smoke fails on any console error (hydration mismatches included), any
leaked `undefined`, and every behaviour it scripts — reading, drilling,
deviations, notes, drawing. jsdom has no layout engine, so design changes still
get a human look at a phone width and a desktop one; every pull request carries
a preview link for exactly that.

## Publishing

Push to `main`. CI runs the Python suite, emits the JSON, builds and smokes the
site, and ships `web/out` to https://chesslab.dev via Cloudflare Pages. Every
pull request gets the whole site at `https://<branch>.chesslab.pages.dev`,
posted as a comment on the PR.

## Design notes

- **Engine truth or no claim.** Severities are calibrated against Stockfish,
  win bars are counted from master games, and the browser computes no chess —
  legality comes from the compiler's packed move lists, scores from the shipped
  evals. The one deliberate exception is personal notes, which render in their
  own card, in their own colour, as opinions.
- **Static export, deliberately.** The data is compiled ahead of time and the
  learner's own state (drill scores, streaks, notes — localStorage key
  `chesslab`) never leaves the browser, so a server would have nothing to do.
  If accounts or sync ever arrive, the seams are `web/lib/content/load.ts` and
  `web/lib/db.ts`.
- **The board speaks a small language.** Yellow fill: the move just played.
  Purple fill and purple arrows: your notes. Green arrow: the move; red: what
  it attacks. A knight-shaped arrow bends only when a piece is making the jump.
