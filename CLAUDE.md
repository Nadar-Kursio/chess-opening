# chess-opening

An interactive opening course, live at https://chesslab.dev. Two halves with a
one-way pipe: `src/` is the Python content compiler — authoring, engine
verification, derivation — and `web/` is the Next.js site (static export) that
consumes the JSON it emits. The wiki's Architecture page explains the moving
pieces.

`src/app/` is the retired single-file client. It is frozen: CI keeps it green
as the rollback path until demolition, but new work happens in `web/`.

## Commands

`build.py` writes relative to the current directory, so in a worktree you must
`cd` into it first or you will rebuild `main` instead of your branch.

```
.venv/bin/python3 src/build.py --emit           # write web/content/ for the site
.venv/bin/python3 -m unittest discover tests    # content + emit contract (+ legacy smoke)
.venv/bin/python3 src/build.py                  # legacy single-file build into docs/
```

The site, from `web/` (after `--emit`):

```
npm ci            # once
npm run dev       # preview on localhost
npm run build     # static export into web/out/
npm test          # jsdom smoke driving the exported pages in web/out/
```

System `python3` has no `python-chess`; use the venv. The legacy smoke needs
jsdom at the repo root (`npm install jsdom` once); `node_modules/` is gitignored.

## Rules

- Generated, never edited, never committed: `docs/`, `web/content/`, `web/out/`.
- Every claim about a position comes from the engine, never from memory —
  severities from `.engine/stockfish`, game scores and win bars (`record`) from
  pgnmentor. The `opening-research` skill has the procedure. The browser is
  equally chess-ignorant: legality is the build's packed `legal` strings,
  scores are the shipped evals — never compute either client-side.
- `src/content/evals/*.json` is one Stockfish score per position, generated by
  the skill's `position-evals.py` and committed. Never hand-edit one.
  **Re-run it after editing any line, deviation or game of a covered opening**,
  or the eval bar quietly loses the plies you moved; the build warns and
  `tests/test_content.py` fails.
- Adding an opening to the site is data-only: author a `slug` per line and add
  the id to `PORTED` in `src/build.py`. If the app needs code to accommodate a
  new opening, that is a bug in the app.
- Personal notes are deliberately unverified — `src/content/notes/` and the
  notes written in the browser (stored by position, localStorage key
  `chesslab`). They render in their own card in their own colour; never fold
  them into the coached commentary or present them as checked. Note text is
  user input: escape it at render, exactly once.
- `web/styles/tokens.css` is the design system. No file below it names a raw
  colour or a raw pixel size; add a token rather than a literal.
- Browser-layer tests use jsdom, not Playwright. `web/tests/smoke.mjs` drives
  the real export in `web/out/` — add a step for anything new, selecting by
  class or ARIA, not element ids. jsdom has no layout engine, so after a
  styles change, look at the page on a phone width as well as a desktop one.
- Changes under `.github/workflows/` can read repository secrets. Review them
  as security changes, not as config.

## Deploying

Push to `main`; CI tests both halves, builds, and ships `web/out` to
https://chesslab.dev. Every pull request gets the whole site at
`https://<branch>.chesslab.pages.dev`, posted as a comment on the PR.
